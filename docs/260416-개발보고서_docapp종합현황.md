# docapp(DevManager Pro) 개발 종합 보고서

**작성일**: 2026-04-16  
**프로젝트**: docapp — 패키지명 `devmanager-pro`  
**목적**: 앱 개발 과정에서 기획서·보고서·프롬프트·메모·이슈·스크린샷 등을 한곳에서 관리하는 웹 애플리케이션

---

## 1. 요약

docapp은 **Firebase(Firestore, Storage, Authentication)** 를 백엔드로 사용하고, **React 18 + TypeScript + Vite** 로 구현된 SPA입니다. **Google 로그인** 후 프로젝트(앱) 단위로 문서와 파일을 관리하며, 최근 개발에서는 **목록 테이블의 컬럼 리사이즈·시각적 구분선 개선**, **프롬프트/참고 등에서의 다중 첨부·인라인 이미지**, **TipTap 기반 WYSIWYG 「프리」 문서 탭**, **카드형 메모 탭** 등이 추가·정비되었습니다.

## 2. 기술 스택

| 구분 | 기술·버전(주요) |

## 3. 애플리케이션 구조

### 3.1 라우팅·인증

- `App.tsx`: `AuthProvider` + `HashRouter`, 보고서용 테이블 세로 구분선 전역 스타일(`.report-table-separators`).
- 공개: `/help`, `/privacy`, `/login`.
- 보호: `/`(대시보드), `/app/:id`(앱 상세). 미인증 시 `/login`으로 이동(`ProtectedRoute`).
- `AppRoutes`: 로딩 중 스피너, 이미 로그인 시 `/login` 접근 시 `/`로 리다이렉트.

### 3.2 데이터 계층

- `services/storage.ts`: Firebase 초기화, Firestore `getCollection` / `saveDocument` / `deleteDocument` 헬퍼, 앱·하위 컬렉션별 API.
- `services/fileService.ts`: Storage 업로드·삭제, 로그인 사용자 필수, 경로 규칙 `entityId/section/timestamp_파일명`.
- `services/authService.ts`: Google 로그인·세션( `AuthContext`에서 사용).

### 3.3 도메인 타입(`types.ts`)

- `AppProject`: 프로젝트 메타(이름, 설명, 버전, 플랫폼, 생성 시각).
- 하위 항목: `PlanningDoc`, `Report`, `PromptLog`, `Memo`, `FreeDoc`, `Issue`, `Screenshot`, `Note`.
- 공통: `BaseItem`(id, appId, title, createdAt, updatedAt). 첨부는 `fileInfo` 단일 및 하위 호환용, `fileInfoList` 다중 첨부 병행.

## 4. 화면·기능별 현황

### 4.1 대시보드(`Dashboard.tsx`)

- 앱 프로젝트 CRUD, 검색, Google 계정 표시·로그아웃.
- 목록 테이블: **`useResizableColumns`** 로 컬럼 폭 조절(드래그), 기본 폭 배열로 초기 레이아웃 지정.

### 4.2 앱 상세(`AppDetail.tsx`)

사이드바 **8개 탭**:

| 탭 | 라벨 | 컴포넌트 | 요약 |
|----|------|----------|------|
| planning | 기획서 | `PlanningView` | 마크다운 편집·미리보기, 첨부 업로드 |
| reports | 보고서 | `ReportView` | 유형·요약·다중 첨부, 마크업/일반 편집 등 |
| prompts | 프롬프트 | `PromptView` | 태그, **RichPromptField**(contentEditable, 클립보드/이미지, 마크다운 이미지 미리보기) |
| memos | 참고 | `MemoView` | 텍스트·첨부, 목록 컬럼·attachment UI 정비 이력 |
| free | 프리 | `FreeDocView` | **TipTap HTML** 저장, 인라인 이미지(드롭·붙여넣기 → Storage), `freeDocs` |
| notes | 메모 | `NoteView` | **카드형** 메모 생성·수정·삭제, 전체화면 상세 편집 전환 |
| issues | 트러블슈팅 | `IssueView` | 상태·심각도, 첨부, UI(신규 이슈 모달 저장 버튼 위치 등) |
| screenshots | 스크린샷 | `ScreenshotView` | 이미지 URL·설명 |

### 4.3 `TabViews.tsx` 중심 기능

- **다중 첨부**: `getFileList()`로 `fileInfoList` / `fileInfo` 통합 처리.
- **프롬프트**: `renderMarkdownImages`, `RichPromptField`, 비동기 업로드 시 selection 보존 등 클립보드 이미지 붙여넣기 관련 수정 이력.
- **보고서**: attachment 컬럼 폭·텍스트 overflow 처리, select UI 정리 등.
- **기획서**: 상세 편집 시 첨부 업로드 기능 추가.
- **테이블 UX**: 헤더·본문 컬럼 세로선(border), 블랙 라인·inset 스타일, 행 높이 축소, 컬럼 라벨 정정, “목록으로” 버튼 톤 통일 등 다수 커밋으로 정제됨.

### 4.4 프리 문서(`FreeDocView.tsx`)

- Firestore 컬렉션 **`freeDocs`**, 본문 필드 **`html`**.
- TipTap: 제목(2/3단), 굵게/기울임/취소선, 목록, 실행 취소·다시 실행, BubbleMenu, 이미지 확장.
- 이미지: `freeDocs/{docId}/inline` 경로로 업로드, **최대 10MB** 검증.
- 확장 배열 `useMemo`로 안정화하여 **이미지 삽입 후 본문이 초기화되던 문제** 수정.

### 4.5 정적 페이지

- `HelpPage`, `PrivacyPage`: 도움말·개인정보 처리 방침(연락처는 `constants/contact.ts` 등과 연계).

## 8. 제한 사항·후속 제안

1. **Leaflet**: 의존성만 있고 UI 미사용이면 번들 크기·유지보수 관점에서 제거 또는 실제 지도 기능 구현 중 선택이 필요합니다.  
2. **README.md**: 여전히 AI Studio / GEMINI_API_KEY 안내 중심으로, 실제 docapp 실행 방법(Firebase 설정, `npm run dev`)과 맞지 않을 수 있어 문서 정리 여지가 있습니다.  
3. **보안**: 클라이언트에 Firebase 설정이 포함되어 있으므로, 운영 시 **Firestore·Storage 규칙**을 인증 사용자 기준으로 엄격히 유지해야 합니다(저장소 규칙 관련 MD 참고).  
4. **로깅**: 라우팅·인증 경로에 `console.log`가 다수 있어 프로덕션에서는 레벨 분리 또는 제거를 검토할 수 있습니다.

## 9. 결론

docapp은 **인증된 사용자 기준의 멀티 프로젝트 문서 허브**로서 기능 범위가 넓어졌고, 특히 **리치 텍스트·이미지·다중 첨부·목록 테이블 사용성**이 강화된 상태입니다. 본 보고서는 저장소 현재 상태를 기준으로 한 **종합 스냅샷**이며, 세부 설계 변경 시 `types.ts`, `storage.ts`, `TabViews.tsx`, `FreeDocView.tsx`를 함께 추적하는 것이 가장 정확합니다.
