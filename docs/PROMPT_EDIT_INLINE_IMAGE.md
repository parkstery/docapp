# 프롬프트 편집 창: 이미지 직접 붙여넣기 및 인라인 편집 방안

## 목표
- 편집 창에서 **클립보드 이미지를 붙여넣으면 곧바로 이미지가 보이고**, 그 옆·아래로 텍스트를 이어서 편집할 수 있게 한다.

## 채택한 방안: contentEditable + 마크다운 직렬화

### 요약
- **User Prompt** / **AI Response** 입력을 **textarea** 대신 **contentEditable** div로 바꾼다.
- 붙여넣기 시 이미지면 업로드 후 **`<img>` 를 커서 위치에 삽입**해, 편집 창 안에서 바로 이미지가 보이게 한다.
- 저장 시 contentEditable 내용을 **기존과 동일한 형식**(텍스트 + `![이미지](url)`)으로 직렬화해 저장하므로, Firestore 스키마·기존 데이터와 호환된다.

### 동작
1. **로드**: 저장된 문자열의 `![alt](url)` 를 HTML `<img>` 로 바꿔 contentEditable 에 넣는다. → 기존에 저장된 이미지도 편집 화면에서 그림으로 보인다.
2. **붙여넣기**: 클립보드에 이미지가 있으면 업로드 후 `<img src="업로드된URL">` 를 커서 위치에 삽입하고, 곧바로 화면에 표시한다.
3. **편집**: 텍스트와 이미지를 한 편집 영역에서 같이 수정할 수 있다.
4. **저장**: contentEditable DOM을 순회해, 텍스트는 그대로 두고 `<img>` 는 `![alt](url)` 로 바꿔 하나의 문자열로 만든 뒤 `editForm.prompt` / `editForm.response` 에 넣어 기존대로 저장한다.

### 장점
- **편집 창에서 바로 이미지 확인·이어쓰기** 가능.
- **저장 형식·API 변경 없음**: 기존 마크다운 이미지 문법 그대로 사용.
- **미리보기**는 그대로 두어, 아래에서도 동일 내용 확인 가능.

### 기술 포인트
- `storedToEditorHtml(text)`: 저장 문자열 → contentEditable용 HTML (이미지 인라인).
- `editorDomToStored(el)`: contentEditable DOM → 저장용 문자열 (이미지 문법 복원).
- `RichPromptField`: contentEditable + paste 시 이미지 업로드·삽입·상태 동기화.
- 프롬프트 전환 시 `key={editForm.id}` 로 리마운트해, 선택한 프롬프트의 초기값이 올바르게 적용되도록 함.

## 대안 (참고)
- **리치 에디터 라이브러리**(TipTap, Slate 등): 더 풍부한 편집 기능 가능하나 의존성·학습 비용 증가.
- **분할 뷰(소스 + 미리보기)**: textarea 유지하고 미리보기만 강화하는 방식은, “편집 창 안에서 직접” 이미지를 보는 요구에는 부합하지 않음.
