# 에디터·저장 포맷 로드맵 (4단계)

**작성일**: 2026-04-16

장기 계획서의 **4단계: 에디터 전략**을 구체화한 문서입니다. 구현 일정은 별도로 잡습니다.

## 1. 현재 상태

| 영역 | 저장 형태 | 비고 |
|------|-----------|------|
| 기획서 | Markdown 문자열 | 미리보기 별도 |
| 보고서 | 요약 문자열 + 첨부 | 마크업/일반 모드 |
| 프롬프트 | prompt/response 문자열 + Rich contentEditable | 이미지는 마크다운+img 혼합 |
| 참고·메모·이슈 | 텍스트 위주 | 첨부 가능 |
| 프리 | TipTap **HTML** | `freeDocs` |

## 2. 프리(TipTap)

- **단기**: HTML 저장 유지, Export 파이프라인에서 HTML→Markdown/Plain 변환.
- **중기**: `editor.getJSON()` 기반 **ProseMirror JSON** 저장 검토 — diff, 버전, 변환 파이프라인에 유리.
- **병행**: 기존 HTML 문서 읽기 호환(마이그레이션 또는 읽기 시 한 번 변환).

## 3. 프롬프트 Rich 필드

- **옵션 A**: TipTap으로 통일해 프리와 동일 스택(학습 비용·번들 크기 트레이드오프).
- **옵션 B**: “Plain + `![](url)`” 로 단순화하고 인라인 이미지는 마크다운 문법만 유지.

의사결정 기준: 프롬프트 편집 빈도, 붙여넣기 UX 요구 수준.

## 4. 기획서

- Markdown 유지가 자연스러움.
- 장기적으로는 **공통 Export**만 강화해도 목표(보고서 가독성·Notion 붙여넣기)에 부합 가능.

## 5. 비목표

- Notion 수준의 블록 단위 협업 에디터 전면 도입은 범위 외.
